# Output Quality Standard
<!-- rule:output -->

## 完成した文章

利用者・開発者が必要とする仕様、操作、状態を自然な文章で提示する。UIや公開成果物へ内部都合・仮文言・ルール遵守の自己説明を追加しない。Templateのplaceholderは実際に配置・出力するときに置換する。

## 報告

完了変更、実際の検証結果、現状、次作業へ影響する課題を簡潔に伝える。実装済み・検証済み・Done・公開済みを区別する。
意味のない非実施事項や遵守説明は省く。ただし利用・受入・公開判断に影響する未検証、失敗、未生成、未反映、必要な権限や外部環境は明示する。簡潔さを理由に重要な不確実性を隠さない。

## 正確性

PASS、Done、Production Ready等は定義されたgateとEvidenceがある場合だけ使用する。検証の詳細結果はEvidenceに保持し、報告は必要な情報を参照付きで要約する。推測と実測を区別する。
同一概念の用語・状態を統一し、公開文書と正本を矛盾させない。
